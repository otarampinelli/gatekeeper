Why it's different

No API keys, no CI wiring

It runs inside the agent you already have open — Claude Code, Cursor, or any tool that reads the skills convention. Nothing extra to configure.

Checks are just markdown

A check is frontmatter plus a plain-English prompt describing what to look for. No plugin API, no DSL to learn.

Isolated, parallel review

Checks are gated by which files actually changed, grouped, then run in parallel sub-agents so one check's reasoning can't bleed into another's verdict.

Verified before you see it

Every candidate finding goes through an adversarial verification pass. Nothing gets reported just because an agent said so.

Local or PR mode

Review your working tree before you push, or point it at a GitHub PR — it fetches the diff via gh and can post findings back as inline comments.

Fix it right there

Every finding comes with a colored diff and a Fix it / Skip choice, so you resolve issues in the same pass you found them.

How it works

01

Gate

Skip checks whose applies_to globs don't match any changed file.

02

Group

Checks sharing a group run together in one agent; everything else gets its own.

03

Judge

Your coding agent reviews the diff against each check's prompt, in parallel.

04

Verify

Candidate findings are double-checked adversarially before anything is shown to you.

Ships with 10 default checks

Security Review Code Quality Test Coverage Anti-Slop Completeness Dead-End Code Documentation Impact Prose Style Scope Fidelity Simplicity

A check is just this

--- name: Security Review description: Flag security issues in the diff hints: - Use when a change touches auth, permissions, or external input handling. --- Review the diff. Fail the check if any of these are true: - Hardcoded API keys, tokens, or passwords - New endpoints without input validation - SQL queries built with string concatenation If none are found, pass the check.
